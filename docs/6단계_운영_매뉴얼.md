# 6단계: 운영 매뉴얼 (TactiCore)

> ⚠️ **이 문서의 명령어는 아직 실행 검증되지 않았습니다.** 코드가 작성되기 전에 설계 문서(2·3단계)를 근거로 미리 작성한 매뉴얼입니다. 구현 완료 후 `5단계_기능_완료_보고서.md`의 항목 6-4-2에서 실제로 실행해 보고 정정해야 합니다.
>
> TactiCore MVP는 **공개 배포 없이 PC에서 로컬 실행**합니다. Docker는 사용하지 않습니다.

## 1. 최초 설치

### 1.1 사전 요구사항

| 항목 | 버전 | 확인 명령 |
| --- | --- | --- |
| Python | 3.11 이상 | `python --version` |
| Node.js | 20 이상 | `node --version` |
| npm | 10 이상 | `npm --version` |

### 1.2 백엔드 설치

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

PowerShell에서 `Activate.ps1` 실행이 차단되면 실행 정책을 현재 사용자에 한해 완화합니다.

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

### 1.3 프론트엔드 설치

```powershell
cd frontend
npm install
```

## 2. 실행

### 2.1 한 번에 실행 (권장)

```powershell
.\scripts\dev.ps1
```

백엔드·프론트엔드 창을 각각 띄우고 브라우저를 엽니다.

### 2.2 개별 실행

터미널 두 개가 필요합니다.

```powershell
# 터미널 1 — 백엔드
cd backend
.\.venv\Scripts\Activate.ps1
uvicorn main:app --reload --port 8000
```

```powershell
# 터미널 2 — 프론트엔드
cd frontend
npm run dev
```

### 2.3 접속 주소

| 대상 | 주소 |
| --- | --- |
| 앱 | http://localhost:5173 |
| API | http://localhost:8000/api |
| API 문서 (Swagger) | http://localhost:8000/docs |

### 2.4 종료

각 터미널에서 `Ctrl+C`. `dev.ps1`로 띄운 경우 생성된 두 PowerShell 창을 각각 닫습니다.

### 2.5 백엔드 없이 사용하기

백엔드를 띄우지 않아도 앱은 동작합니다. 다음 기능만 비활성화됩니다.

| 기능 | 백엔드 없이 |
| --- | --- |
| 전술 편집, 국면 전환, 공간 레이어 | ✅ 사용 가능 |
| PNG 카드 내보내기 | ✅ 사용 가능 |
| JSON 내보내기 / 가져오기 | ✅ 사용 가능 |
| 분석 저장 / 목록 조회 / 삭제 | ❌ 비활성화 |

즉 저장만 안 될 뿐이므로, 급할 때는 백엔드 없이 작업하고 **JSON 내보내기로 결과를 보관**하면 됩니다.

## 3. 데이터 관리

### 3.1 DB 파일 위치

```
backend/tacticore.db
```

SQLite 단일 파일입니다. Git에 커밋되지 않도록 `.gitignore`에 등록되어 있습니다.

### 3.2 백업

서버를 종료한 뒤 파일을 복사합니다.

```powershell
Copy-Item backend\tacticore.db "backend\backup\tacticore_$(Get-Date -Format 'yyyyMMdd').db"
```

서버가 실행 중일 때 복사하면 쓰기 도중의 상태가 복사될 수 있습니다. 정기 백업은 서버 종료 후 수행하세요.

### 3.3 다른 PC로 이관

`tacticore.db` 파일 하나만 옮기면 됩니다. 대상 PC에서 설치(§1)를 마친 뒤 `backend/` 아래에 덮어씁니다.

### 3.4 초기화

```powershell
# 주의: 저장된 모든 분석이 삭제됩니다
Remove-Item backend\tacticore.db
```

다음 서버 기동 시 빈 DB가 자동 생성됩니다. 삭제 전에 §3.2 백업을 먼저 하세요.

### 3.5 스키마 변경 시

MVP는 마이그레이션 도구(Alembic)를 쓰지 않습니다. 모델을 변경하면 기존 `tacticore.db`와 구조가 어긋납니다. 절차:

1. 기존 분석을 앱에서 **JSON으로 내보내기** (§4.1)
2. `tacticore.db` 삭제
3. 서버 재기동 (새 스키마로 생성)
4. 내보낸 JSON을 **가져오기** 후 다시 저장

## 4. JSON 입출력 가이드

DB와 별개로, 분석 1건을 파일로 주고받는 수단입니다.

### 4.1 내보내기

편집 화면에서 `JSON 내보내기` → `.json` 파일이 다운로드 폴더에 저장됩니다. 이 파일은 백업, 다른 PC로의 이동, 스키마 변경 시 재적재에 모두 쓸 수 있습니다.

### 4.2 가져오기

`JSON 가져오기`에서 파일을 선택합니다. 형식이 어긋나면 어느 위치가 잘못됐는지 안내가 표시됩니다. 자주 나오는 오류:

| 오류 | 원인 | 조치 |
| --- | --- | --- |
| 좌표 범위 초과 | `x` 또는 `y`가 0~100을 벗어남 | 값을 백분율로 수정 |
| 선수 수 불일치 | `players`가 11명이 아님 | 11명으로 맞춤 |
| 상대팀 좌표 개수 오류 | `opponentPositions`가 있는데 11개가 아님 | 11개로 맞추거나 항목 전체를 삭제 |
| 국면 누락 | `base`/`attack`/`defense` 중 빠짐 | 세 국면 모두 포함 |
| 날짜 형식 | `matchDate`가 `YYYY-MM-DD`가 아님 | 형식 수정 |

### 4.3 샘플 파일

`frontend/public/samples/`에 샘플 경기 JSON이 있습니다. 처음 사용할 때 이 파일을 가져와 구조를 확인하세요.

## 5. 데이터 입력 가이드

### 5.1 좌표 규칙

- 모든 좌표는 **0~100 백분율**입니다. 미터나 픽셀이 아닙니다.
- `y = 0`이 상대 골라인, `y = 100`이 자팀 골라인입니다. **값이 작을수록 전진한 위치**입니다.
- `x = 0`이 왼쪽 터치라인, `x = 100`이 오른쪽 터치라인입니다.
- 환산 기준은 105m × 68m입니다. `y` 1% ≈ 1.05m, `x` 1% ≈ 0.68m.

### 5.2 채널 경계

| 채널 | x 범위 |
| --- | --- |
| 좌측 측면 | 0 ~ 20 |
| 좌측 하프스페이스 | 20 ~ 36.5 |
| 중앙 | 36.5 ~ 63.5 |
| 우측 하프스페이스 | 63.5 ~ 80 |
| 우측 측면 | 80 ~ 100 |

수직 3분할: 공격 서드 `0~33.3`, 중원 `33.3~66.7`, 수비 서드 `66.7~100`.

### 5.3 오버로드 레이어를 쓰려면

상대팀 11명의 좌표를 입력해야 활성화됩니다. 입력하지 않으면 토글이 비활성 상태로 표시됩니다. 부분 입력(예: 5명만)은 허용되지 않습니다 — 11명 전부이거나, 전부 없거나입니다.

수적 우위 판정 기준:

| 자팀 − 상대 | 표시 |
| --- | --- |
| 2명 이상 많음 | 진한 하이라이트 |
| 1명 많음 | 옅은 하이라이트 |
| 같거나 적음 | 표시 없음 |

### 5.4 GK 판별

앱은 역할(`role`) 문자열이 아니라 **y값이 가장 큰 선수 1명을 GK로 간주**합니다. 압박 라인 자동 산출과 콤팩트니스 계산에서 이 선수를 제외합니다. 따라서 GK를 필드 중앙까지 끌어올려 배치하면 계산이 틀어질 수 있습니다.

### 5.5 권장 작성 순서

1. `/new`에서 포메이션 프리셋 선택 → 11명 자동 배치
2. 선수 이름·등번호 입력
3. `기본` 국면에서 드래그로 실제 배치 조정
4. `공격` 국면으로 전환 → 해당 국면 대형으로 드래그
5. `수비` 국면 동일하게 조정
6. 국면별 코멘트 + 종합 평가 입력
7. 저장(DB) 또는 JSON 내보내기
8. PNG 카드 내보내기

## 6. 문제 해결

### 6.1 포트가 이미 사용 중

```powershell
# 8000 포트를 쓰는 프로세스 확인
Get-NetTCPConnection -LocalPort 8000 -State Listen | Select-Object OwningProcess
Get-Process -Id <PID>
```

다른 포트로 띄우려면 백엔드는 `--port 8001`, 프론트는 `npm run dev -- --port 5174`. 포트를 바꾸면 `frontend/.env`의 `VITE_API_BASE_URL`과 `backend/.env`의 `CORS_ORIGINS`도 함께 고쳐야 합니다.

### 6.2 저장 버튼이 비활성화됨

백엔드가 실행 중이 아닙니다. `http://localhost:8000/api/health`에 접속해 `{"status":"ok"}`가 나오는지 확인하세요.

### 6.3 CORS 오류

브라우저 콘솔에 `blocked by CORS policy`가 뜨면, 프론트 주소가 `backend/.env`의 `CORS_ORIGINS`에 없는 경우입니다. 포트를 바꿨거나 `127.0.0.1`로 접속한 경우 발생합니다 — `localhost`와 `127.0.0.1`은 다른 오리진으로 취급됩니다.

### 6.4 삭제해도 데이터가 남음

`PRAGMA foreign_keys=ON`이 적용되지 않아 CASCADE가 동작하지 않는 경우입니다. `database.py`의 이벤트 리스너를 확인하세요(4단계 §2.1).

### 6.5 국면 전환 시 선수들이 서로 자리를 바꿈

Framer Motion의 노드 key가 `player.id`가 아니라 배열 인덱스로 되어 있습니다. 4단계 §5.1 참조.

### 6.6 PNG 카드의 글꼴이 다르게 나옴

`document.fonts.ready`를 기다리지 않고 캡처한 경우입니다. 4단계 §5.3 참조.

### 6.7 PNG 카드가 빈 이미지로 나옴

캡처 대상 노드를 `display:none`이나 `visibility:hidden`으로 숨긴 경우입니다. `position:absolute; left:-9999px`를 사용해야 합니다.

### 6.8 로그 확인

FastAPI 기본 로그가 백엔드 터미널에 출력됩니다. 별도 로그 파일은 MVP에서 만들지 않습니다.

```powershell
# 요청 로그를 파일로도 남기려면
uvicorn main:app --reload --port 8000 --log-config logging.json
```

## 7. 알려진 제약 (MVP)

| 제약 | 사유 | 해소 시점 |
| --- | --- | --- |
| 로컬 실행만 가능, 공개 URL 없음 | 백엔드가 있어 정적 배포 불가 | 2차 (배포 방식 결정) |
| 다중 사용자 미지원, 로그인 없음 | 단일 사용자 전제 | 2차 |
| 마이그레이션 도구 없음 | 스키마 변경 시 DB 재생성 | 2차 |
| 타임라인(자유 시점) 미지원 | MVP는 고정 3국면 | 2차 |
| 다크 모드·다국어 미지원 | MVP 범위 축소 | 2차 검토 |
| 상대팀 선수는 이름·등번호 없음 | 좌표만 저장 | 필요 시 재검토 |
