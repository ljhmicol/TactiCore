### 3. 감독 프리셋 추가

- **내용**: 후보 — 무리뉴, 안첼로티, 투헬, 포체티노 등 + K리그 감독. `frontend/public/samples/managers/`에 JSON 추가 + `ManagerPresetPicker` 배열 등록이 전부.
- **유의**: 좌표는 공개 전술 분석 기반 재구성(실제 트래킹 아님) — 기존 프리셋과 같은 주석 유지. 감독 최신 이력(해임·이적)은 추가 시점에 다시 확인한다.

### 4. 상대팀 프리셋

- **상태**: 2026-09-08 사용자 요청("2,3번 말고 다른거") → 구현 완료(`[O]`), 사용자 확인 전
- **내용**: 오버로드 레이어는 `opponentPositions`가 있어야 동작하는데 기존 "상대팀 추가" 버튼은 자팀 현재 배치를 그대로 대칭 복사할 뿐이라 자팀과 다른 모양(예: 4-4-2 로우블록)을 표현하려면 11개 점을 일일이 드래그해야 했다. 피치 아래에 "상대 포메이션" 드롭다운(18종 포메이션 이름, `FORMATION_NAMES` 재사용)을 추가해 선택 즉시 그 포메이션 템플릿을 대칭 배치한다.
- **구현**:
  - `store/analysisStore.ts`에 `addOpponentsFromFormation(formationName)` 신규 액션 — 기존 `addOpponents`(자팀 현재 좌표 대칭)와 별개로, `FORMATIONS[formationName]` 템플릿 좌표를 같은 대칭 공식(`y' = 100 - y`, x는 그대로)으로 변환해 현재 국면의 `opponentPositions`에 넣는다. 존재하지 않는 포메이션 이름은 조용히 무시(상태 불변)
  - 기존 `addOpponents` 버튼("상대팀 추가"/"상대팀 제거")은 그대로 유지 — 자팀과 동일한 배치를 원할 때의 빠른 기본값으로 남겨둠. 드롭다운은 그 옆에 나란히 배치해 "다른 모양"을 원할 때만 쓰는 보조 수단
  - 국면별로 독립 적용(기존 `addOpponents`와 동일하게 `currentPhase`에만 반영) — 자팀 공격 국면엔 상대가 로우블록(4-4-2), 수비 국면엔 상대가 하이프레스(4-3-3) 같은 국면별 다른 상대 모양을 표현할 수 있음
- **검증**: vitest 82개(5개 신규 — 템플릿 대칭 계산 정확성, 자팀과 다른 모양 확인, 국면별 독립 적용, 존재하지 않는 이름 무시, zod 스키마 통과)·eslint·tsc·빌드 클린. Playwright로 빈 4-3-3 새 분석에서 드롭다운으로 "4-4-2" 선택 → 상대 GK가 y≈8(4-4-2 템플릿 GK y=92의 대칭)에 배치되는 것, "상대팀 제거" 버튼이 나타나는 것(상대 배치 확인), 오버로드 레이어 토글이 활성화되는 것(이전엔 상대 없어 비활성) 확인

### 5. 타임라인 (매치 체인징 포인트)

- **내용**: 3국면 고정을 넘어 경기 시간 축에 체인징 포인트를 여러 개 찍고 시점별 대형 저장. "전반 23분 추격 상황" 재현.
- **기술 메모**: 프론트 스토어·zod가 이미 대비함 — `convertKeys`가 `phases` 맵 키를 보호하는 이유가 이 확장이다(`api.ts` 주석 참조). 국면 키가 `base/attack/defense`에서 벗어나도 깨지지 않음. DB `phases.phase_type`은 문자열이라 호환. UI(타임라인 바)가 주 공수.

### 6. GIF/영상 내보내기

- **상태**: 2026-09-08 사용자 요청("조사해줘" → "구현 시작해줘") → 조사 후 구현 완료(`[O]`), 사용자 확인 전
- **내용**: 국면 전환 모핑 애니메이션(기본→공격→수비→기본 순환)을 SNS용 GIF로. PNG 다음 자연스러운 확장.
- **조사 결과 — MediaRecorder 대신 GIF를 택한 이유**: `MediaRecorder`는 `<canvas>`/`<video>`의 실시간 스트림(`captureStream()`)이 필요한데 피치는 SVG라 직접 스트리밍이 안 되고, 결국 SVG를 canvas로 매 프레임 래스터화해야 하는 건 GIF 방식과 동일하게 필요하다. 출력 포맷도 브라우저 기본 WebM이라 MP4 변환에 ffmpeg.wasm 같은 무거운 걸 더 붙여야 하고, 실시간 녹화 방식이라 프레임 타이밍이 기기 성능에 좌우된다 — PNG 내보내기가 "반응형 뷰포트를 그대로 캡처하면 기기마다 결과가 달라진다"며 일부러 피한 것과 같은 문제가 재발한다. GIF는 어느 플랫폼에서나 자동재생되고, 이 앱처럼 평면색 위주 콘텐츠엔 256색 제한이 거의 안 보인다. 인코더는 워커 파일을 `public/`에 따로 복사해야 하는 `gif.js`(2013년산, 유지보수 사실상 중단) 대신 의존성 0개·통합이 간단한 `gifenc`(mattdesl, 172KB, 타입 선언은 없어서 `types/gifenc.d.ts`로 직접 선언)를 채택
- **구현**:
  - **실시간 녹화가 아니라 가상 시간 스테핑**: Framer Motion의 실제 재생을 녹화하는 대신, 국면 사이 중간 좌표를 미리 계산해(`lib/exportGif.ts`의 `interpolatePositions` + `easeInOutCubic`) 정지 이미지를 순서대로 캡처한다 — 기존 PNG 캡처("모프 끝날 때까지 기다렸다 찍기")와 같은 결정론적 철학이라 캡처 타이밍이 기기 성능에 흔들리지 않는다
  - `buildGifFrameSpecs`가 기본→공격→수비→(기본으로 순환) 프레임 시퀀스를 만든다. 각 국면은 정지 프레임 하나 + `delay` 값으로 "머무는 시간"을 표현하고(같은 프레임을 여러 장 찍지 않음), 국면 사이는 12단계로 보간해 편집 화면의 모프 시간(`PHASE_TRANSITION_MS`)과 체감 속도를 맞춘다 — 실제 프리셋 기준 총 39프레임(정지 3 + 전환 36)
  - 코멘트·화살표·상대팀·압박 라인·오버로드처럼 위치 보간이 안 되는 요소는 국면이 바뀌는 "시작" 시점에 곧바로 도착 국면 것으로 스냅한다 — 편집 화면에서 국면 탭을 누르면 코멘트 패널은 즉시 바뀌고 선수 위치만 뒤따라 움직이는 것과 같은 규칙
  - `PrintPlayerNode` 신규 — `PlayerNode`의 정지 상태(색·라벨)를 그대로 재현하되 Framer Motion·스토어 결합을 뺐다. 프레임마다 다른(보간된) 좌표를 그 순간 즉시 그려야 해서 라이브 애니메이션 컴포넌트를 그대로 쓰면 캡처마다 트랜지션이 걸려 흔들린다 — `StaticPlayerNode`(전술 대결 뷰, 팀 단위 색상)와 같은 이유의 분리
  - `AnimatedShareCard` 신규 — `ShareCard`(PNG)와 같은 레이아웃이지만 `phaseType` 대신 프레임(`GifFrameSpec`)을 받는다. GIF는 프레임을 수십 장 인코딩해야 해서 카드 크기를 PNG(1080)보다 작은 720으로, 비율도 1:1 하나로 좁혔다
  - `GifExportRunner` 신규 — React state(`index`)로 프레임을 하나씩 진행하며 두 번의 `requestAnimationFrame`으로 페인트를 기다린 뒤 `html-to-image`의 `toCanvas`로 캡처(PNG 경로와 같은 함수 재사용), 다 모으면 `encodeGif`(gifenc, 프레임별 256색 개별 양자화, `repeat:0`로 무한 반복)로 인코딩해 다운로드
- **검증**: vitest 10개 신규(이징 함수 단조성, 보간 경계값 t=0/0.5/1, 순환 시퀀스, 프레임 수·delay 양수 검증)·eslint·tsc·빌드 클린. Playwright로 아르테타 프리셋에서 "GIF 내보내기" 클릭 → 실제 다운로드된 파일이 유효한 GIF89a 헤더, 2.7초 내 완료, ~0.9MB 확인. `omggif`로 직접 디코딩해 프레임 수(39, 설계값과 정확히 일치)·프레임별 delay(정지 1100ms/전환 50ms×12)·총 재생 시간(5.1초) 검증, 중간 프레임을 PNG로 추출해 실제로 피치·선수(포지션 라인 색상)·화살표·압박 라인·코멘트·벤치가 전부 정상 렌더링된 것을 육안 확인

### 9. 실제 경기 명장면 프리셋 (StatsBomb OpenData)

- **내용**: 원래 원했던 "실제 경기 분석"의 부분 실현. StatsBomb OpenData(무료, GitHub 공개)의 이벤트 데이터에는 슈팅 순간 양 팀 전원의 실제 좌표(freeze frame)가 담겨 있어, 이를 국면 프리셋으로 변환하면 "2022 월드컵 결승 결승골 장면" 같은 실제 배치를 불러올 수 있음.
- **제약 (중요)**: 슈팅 장면 위주(전 경기 트래킹 아님), 좌표계 변환(StatsBomb는 0~120 × 0~80) 필요, 원본 JSON이 커서 사전 가공 스크립트 필요. 작업량 중~대.
- **연혁**: "실제 경기를 DB에서 검색해 자동 분석"은 2026-09-01 무료 API가 국면별 선수 좌표를 제공하지 않아 기각 → 감독 프리셋으로 대체. 이 항목은 그 대안의 확장.

### 10. 배포 (Docker)

- **기술 메모**: 컨테이너에서 `npm run build` → FastAPI가 `dist/`를 StaticFiles로 서빙하는 단일 이미지 구성이 가장 단순. 개발은 계속 로컬 2프로세스.
