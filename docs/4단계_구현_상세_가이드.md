## 2. 백엔드 구현 상세

### 2.1 `database.py` — FK 강제

SQLite는 커넥션마다 FK를 켜야 한다. 이걸 빠뜨리면 `ON DELETE CASCADE`가 조용히 무시되어 고아 행이 쌓인다.

```python
from sqlalchemy import create_engine, event
from sqlalchemy.orm import sessionmaker, declarative_base

from config import settings   # 3단계 §7의 pydantic-settings

engine = create_engine(
    settings.database_url,
    connect_args={"check_same_thread": False},
)

@event.listens_for(engine, "connect")
def _set_sqlite_pragma(dbapi_connection, connection_record):
    cursor = dbapi_connection.cursor()
    cursor.execute("PRAGMA foreign_keys=ON")
    cursor.close()

SessionLocal = sessionmaker(bind=engine, autoflush=False)
Base = declarative_base()
```

### 2.2 `models.py` — 골격

```python
class Analysis(Base):
    __tablename__ = "analyses"
    id = Column(Integer, primary_key=True)
    match_name = Column(String, nullable=False)
    home_team = Column(String, nullable=False)
    away_team = Column(String, nullable=False)
    match_date = Column(String, nullable=False)
    competition = Column(String)
    analyzed_team = Column(String, nullable=False)
    formation = Column(String, nullable=False)
    summary = Column(Text)
    schema_version = Column(Integer, nullable=False, default=1)
    created_at = Column(String, nullable=False)
    updated_at = Column(String, nullable=False)

    players = relationship("Player", back_populates="analysis",
                           cascade="all, delete-orphan")
    phases = relationship("Phase", back_populates="analysis",
                          cascade="all, delete-orphan")
```

`Player`, `Phase`, `Position`은 2단계 §4의 SQL을 그대로 옮긴다. `cascade="all, delete-orphan"`을 relationship에도 지정해야 ORM 레벨 삭제가 하위까지 전파된다(DB의 FK CASCADE와 별개다 — 둘 다 필요).

### 2.3 `crud.py` — 저장/갱신의 핵심

```python
def upsert_analysis(db, payload: schemas.AnalysisIn, analysis_id: int | None = None):
    now = datetime.now().isoformat(timespec="seconds")

    if analysis_id is None:
        row = models.Analysis(created_at=now)
        db.add(row)
    else:
        row = db.get(models.Analysis, analysis_id)
        if row is None:
            raise NotFound
        # 전체 교체: 하위를 비우면 delete-orphan이 처리한다
        row.players.clear()
        row.phases.clear()
        db.flush()

    row.match_name = payload.match.match_name
    # ... 나머지 스칼라 필드
    row.updated_at = now

    # client_id -> Player 매핑을 만들어 두고 좌표에서 참조
    player_map = {}
    for p in payload.players:
        pl = models.Player(client_id=p.id, name=p.name,
                           number=p.number, role=p.role)
        row.players.append(pl)
        player_map[p.id] = pl

    db.flush()   # player_map의 PK 확보

    for phase_type, phase in payload.phases.items():
        ph = models.Phase(phase_type=phase_type,
                          pressing_line_y=phase.pressing_line_y,
                          comment=phase.comment)
        row.phases.append(ph)
        for pos in phase.positions:
            ph.positions.append(models.Position(
                player=player_map[pos.player_id],
                side="own", slot=0, x=pos.x, y=pos.y))
        for slot, pos in enumerate(phase.opponent_positions or []):
            ph.positions.append(models.Position(
                player=None, side="opponent", slot=slot, x=pos.x, y=pos.y))

    db.commit()
    db.refresh(row)
    return row
```

**주의:** `players`의 `client_id`를 그대로 보존해야 한다. 저장할 때 새 id를 발급하면, 불러온 뒤 국면을 전환할 때 노드 동일성이 깨져 모핑이 엉킨다(§5.1).

### 2.4 응답 변환

`GET /api/analyses/{id}`의 응답은 3단계 §2.3의 형태여야 한다. ORM 행을 그대로 직렬화하면 구조가 다르므로, `crud.to_analysis_json(row)`에서 명시적으로 조립한다.

```python
def to_analysis_json(row) -> dict:
    by_pk = {p.id: p.client_id for p in row.players}
    phases = {}
    for ph in row.phases:
        own = [p for p in ph.positions if p.side == "own"]
        opp = sorted([p for p in ph.positions if p.side == "opponent"],
                     key=lambda p: p.slot)
        phases[ph.phase_type] = {
            "positions": [{"playerId": by_pk[p.player_id], "x": p.x, "y": p.y}
                          for p in own],
            "opponentPositions": ([{"x": p.x, "y": p.y} for p in opp]
                                  if opp else None),
            "pressingLineY": ph.pressing_line_y,
            "comment": ph.comment or "",
        }
    # ... match/players/summary 조립
```

## 3. 프론트엔드 구현 상세

### 3.1 `lib/api.ts` — 케이스 변환

```ts
const BASE = import.meta.env.VITE_API_BASE_URL;

const toSnake = (s: string) => s.replace(/[A-Z]/g, c => '_' + c.toLowerCase());
const toCamel = (s: string) => s.replace(/_([a-z])/g, (_, c) => c.toUpperCase());

function convertKeys(value: unknown, fn: (s: string) => string): unknown {
  if (Array.isArray(value)) return value.map(v => convertKeys(v, fn));
  if (value && typeof value === 'object') {
    return Object.fromEntries(
      Object.entries(value).map(([k, v]) => [fn(k), convertKeys(v, fn)])
    );
  }
  return value;
}

export async function apiFetch<T>(path: string, init?: RequestInit): Promise<T> {
  const res = await fetch(`${BASE}${path}`, {
    ...init,
    headers: { 'Content-Type': 'application/json', ...init?.headers },
    body: init?.body ? JSON.stringify(convertKeys(JSON.parse(init.body as string), toSnake)) : undefined,
  });
  if (!res.ok) throw await toApiError(res);
  if (res.status === 204) return undefined as T;
  return convertKeys(await res.json(), toCamel) as T;
}
```

**변환에서 제외해야 하는 키가 있다.** `players[].id`는 `p1` 같은 문자열이라 문제없지만, `phases` 객체의 키(`base`/`attack`/`defense`)와 선수 id는 **값이지 필드명이 아니다.** 위 재귀 변환은 객체 키를 전부 바꾸므로, `phases`처럼 "키가 데이터인" 맵을 만나면 그대로 두도록 예외 처리를 넣어야 한다. `base`/`attack`/`defense`는 단어 하나라 변환해도 그대로지만, 향후 타임라인(2차)에서 키가 복잡해지면 깨진다.

### 3.4 좌표 변환 (`lib/coords.ts`)

SVG `viewBox="0 0 100 100"`에 `preserveAspectRatio="xMidYMid meet"`를 쓰면, 화면 비율에 따라 좌우 또는 상하에 여백이 생긴다. 마우스 좌표를 피치 좌표로 바꿀 때 이 여백을 빼야 한다. `SVGGraphicsElement.getScreenCTM().inverse()`를 쓰면 이 계산을 직접 하지 않아도 된다.

```ts
export function clientToPitch(svg: SVGSVGElement, clientX: number, clientY: number) {
  const pt = svg.createSVGPoint();
  pt.x = clientX; pt.y = clientY;
  const { x, y } = pt.matrixTransform(svg.getScreenCTM()!.inverse());
  return { x, y };
}
```

## 5. 특수 기능 구현 주의사항

### 5.1 모핑 노드 동일성 — 가장 중요한 규칙

Framer Motion은 **React key로 노드를 추적**한다. 국면을 전환할 때 선수 배열의 순서가 바뀌면, key가 인덱스인 경우 "3번 노드"가 다른 선수를 가리키게 되고, 화면에서는 선수들이 서로 자리를 바꾸는 이상한 애니메이션이 나온다.

규칙:
- key는 항상 `player.id` (nanoid 문자열).
- 국면 전환 시 배열을 **재정렬하지 않는다.** 정렬이 필요하면 렌더링 직전이 아니라 데이터 로드 시 한 번만 한다.
- 저장/불러오기를 거쳐도 `player.id`가 보존되어야 한다(§2.3의 `client_id`).
- 상대팀 노드는 id가 없으므로 `slot` 인덱스를 key로 쓴다. 상대팀은 개별 식별이 없으므로 이 경우는 허용된다.

### 5.2 오버로드 계산 (`lib/overload.ts`)

```ts
export function computeOverload(phase: PhaseData): ZoneOverload[] {
  const opp = phase.opponentPositions;
  if (!opp || opp.length === 0) return [];      // 레이어 비활성

  const own = phase.positions;
  const result: ZoneOverload[] = [];

  for (const channel of CHANNELS) {
    const [x0, x1] = CHANNEL_BOUNDS[channel];
    for (const third of THIRDS) {
      const [y0, y1] = THIRD_BOUNDS[third];
      // 하한 포함, 상한 배제. 단 마지막 구역(상한 100)만 100을 포함시킨다
      const within = (v: number, lo: number, hi: number) =>
        v >= lo && (hi >= 100 ? v <= 100 : v < hi);
      const inZone = (p: Point) =>
        within(p.x, x0, x1) && within(p.y, y0, y1);

      const ownCount = own.filter(inZone).length;
      const oppCount = opp.filter(inZone).length;
      const diff = ownCount - oppCount;

      result.push({
        channel, third, own: ownCount, opp: oppCount, diff,
        level: diff >= 2 ? 'strong' : diff === 1 ? 'weak' : 'none',
      });
    }
  }
  return result;
}
```

**경계 처리 주의.** 상한을 배제하면 `x = 100`(오른쪽 터치라인 위)이나 `y = 100`(골라인 위)인 좌표가 어떤 구역에도 속하지 않아, 선수 한 명이 계산에서 조용히 사라진다.

드래그 시 `0~99.9`로 클램프하는 것만으로는 부족하다. **JSON 가져오기(FR-07)와 API 조회로 들어오는 좌표는 드래그를 거치지 않으므로 정확히 `100`일 수 있다** — 검증 규칙(3단계 §2.7)이 `0 <= v <= 100`을 허용하기 때문이다. 따라서 위 코드처럼 **계산 함수 자체가 상한 100을 포함**하도록 해야 한다. 드래그 클램프는 그 위의 보조 수단이다.

### 5.4 압박 라인 자동 산출 (`lib/compactness.ts`)

```ts
export function autoPressingLine(positions: PlayerPosition[]): number {
  const sorted = [...positions].sort((a, b) => b.y - a.y);
  return sorted[1]?.y ?? sorted[0].y;   // [0]은 GK로 간주하고 제외
}
```

GK를 `role` 문자열로 판별하지 않는다 — 자유 입력이라 `"골키퍼"`, `"GK"`, 빈 값이 섞인다. **y가 가장 큰 선수 1명을 GK로 간주**하는 규칙이 실용적으로 안전하다. 사용자가 `pressingLineY`를 직접 지정하면 자동 산출을 쓰지 않는다.

### 5.5 콤팩트니스 산출 (`lib/compactness.ts`)

GK를 제외한 자팀 10명의 bounding box를 그리고, 변의 길이를 미터로 환산해 표기한다.

```ts
export function computeCompactness(positions: PlayerPosition[]) {
  const outfield = [...positions].sort((a, b) => b.y - a.y).slice(1);  // GK 제외

  const minX = Math.min(...outfield.map(p => p.x));
  const maxX = Math.max(...outfield.map(p => p.x));
  const minY = Math.min(...outfield.map(p => p.y));
  const maxY = Math.max(...outfield.map(p => p.y));

  return {
    box: { x: minX, y: minY, width: maxX - minX, height: maxY - minY },
    verticalM:   +((maxY - minY) * PITCH_LENGTH_M / 100).toFixed(1),  // y축 = 길이 105m
    horizontalM: +((maxX - minX) * PITCH_WIDTH_M  / 100).toFixed(1),  // x축 = 폭 68m
  };
}
```

- **환산 축을 헷갈리지 말 것.** `y`는 골문 사이 방향이므로 105m, `x`는 터치라인 사이이므로 68m를 곱한다. 반대로 쓰면 수치가 그럴듯하게 나오면서 틀린다.
- 표기는 `세로 32.5m × 가로 41.1m` 형태로 박스 옆에 붙인다.
- 압박 라인과 GK 제외 규칙이 동일하므로, 두 함수는 `outfieldPlayers(positions)` 헬퍼를 공유한다.

### 5.6 포메이션 프리셋 (`lib/formations.ts`)

프리셋은 `base` 국면의 좌표만 제공한다. `attack`/`defense`는 프리셋 좌표를 복사해 초기화하고, 사용자가 드래그로 차이를 만든다.

```ts
export const FORMATIONS: Record<string, Point[]> = {
  '4-3-3': [
    { x: 50, y: 92 },                                             // GK
    { x: 16, y: 74 }, { x: 38, y: 78 }, { x: 62, y: 78 }, { x: 84, y: 74 },
    { x: 50, y: 62 }, { x: 32, y: 52 }, { x: 68, y: 52 },
    { x: 16, y: 30 }, { x: 50, y: 22 }, { x: 84, y: 30 },
  ],
  // '4-4-2', '4-2-3-1', '3-5-2' 동일 형식
};
```

배열 순서는 GK → 수비 → 미드필더 → 공격 순으로 고정한다. `applyFormation`은 이 순서대로 `players[i]`에 좌표를 매핑하므로, 순서가 흔들리면 등번호와 위치가 어긋난다.

### 5.7 shadcn/ui 설치 순서

`npx shadcn@latest init`은 Tailwind 설정과 `components.json`이 이미 있어야 정상 동작한다. 순서: Vite 생성 → Tailwind 설치·설정 → `tsconfig`에 path alias(`@/*`) 추가 → shadcn init → 컴포넌트 추가. alias를 먼저 안 넣으면 생성된 컴포넌트의 import가 전부 깨진다.
